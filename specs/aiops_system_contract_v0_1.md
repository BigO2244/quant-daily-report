# AIOps System Contract v0.1

**Date**: 2026-03-01  
**Status**: HARDEN mode  
**Stability**: Contracts are deterministic and enforced by integration tests.

## Overview

This document specifies the CLI contract, exit codes, and output formats for the AIOps lifecycle commands. All contracts must be deterministic (no random variance, no timestamps beyond those in RUN_ID) and free of secrets.

---

## Contract 1: `aiops parse <spec>`

**Purpose**: Parse and validate a spec file for required headers.

### Stdout (Success)
```json
{
  "MODE": "<mode>",
  "PROJECT_TYPE": "<project_type>",
  "RISK_TIER": "<risk_tier>",
  "OBJECTIVE": "<objective>"
}
```

### Exit Codes
- `0`: Parse successful, headers valid
- `1`: File not found, missing required header, or invalid YAML/markdown syntax

### Invariants
- **Deterministic**: Same spec file always produces same stdout
- **No timestamps**: No datetime values in output
- **Ordered keys**: Alphabetically stable output (via `json.dumps`)

---

## Contract 2: `aiops plan --spec <spec> [--mode <MODE>]`

**Purpose**: Create deterministic planning artifacts (plan.md, spec_snapshot.md) and print artifact locations to stdout.

### Prerequisites
- Valid `.md` spec file with required headers
- `reports/ai_runs/` directory writable
- Git metadata available for short SHA (falls back to "nogit" if unavailable)

### Stdout (Success)
Exactly **4 lines**, newline-separated, on success:
```
RUN_ID: <YYYYMMDD_HHMMSS_<short_sha>>
RUN_DIR: <absolute_path_to_reports/ai_runs/<run_id>>
PLAN_PATH: <absolute_path_to_reports/ai_runs/<run_id>/plan.md>
SPEC_SNAPSHOT_PATH: <absolute_path_to_reports/ai_runs/<run_id>/spec_snapshot.md>
```

### Artifacts Created in `reports/ai_runs/<RUN_ID>/`
1. **plan.md**: Canonical plan document with PLAN_HASH footer
2. **spec_snapshot.md**: Copy of input spec at parse time

### Exit Codes
- `0`: Plan created successfully, artifacts written, 4 lines printed
- `1`: Parse failed, mode invalid, or IO error

### Plan Content (Deterministic)
The plan file contains:
```
PLAN_VERSION: 1
SPEC_PATH: <spec_path>
MODE: <mode>
SPEC_HASH: <sha256_of_spec>

FILES:
<extracted files section>

ACCEPTANCE_CRITERIA:
<extracted acceptance criteria section>

PLAN_HASH: <sha256_of_plan_body>
```

### Invariants
- **Deterministic**: Same spec + mode always produces identical plan.md and run_id (within 1-second window)
- **RUN_ID format**: `YYYYMMDD_HHMMSS_<short_sha>` (timestamp + git short SHA or "nogit")
- **Idempotent within 1-second**: Two rapid calls with same spec/mode produce identical plan
- **No secrets**: Plan.md contains no OPENAI_API_KEY, AWS keys, or other secrets
- **Sorted sections**: FILES and ACCEPTANCE_CRITERIA extracted in stable order

## Contract 3: `aiops verify <spec> [--mode <MODE>]`

**Purpose**: Run mode-gated verification suite on spec.

### Exit Codes
- `0`: All checks passed
- `1`: Spec not found, missing header, or check failed
- `2`: Mode requires operator intervention (e.g., HARDEN with manual review tasks)

### Invariants
- **Deterministic**: Same spec always produces same exit code and output
- **Mode-gated**: Different modes (EXPLORE, BUILD, HARDEN) trigger different check sets
- **No side effects**: Read-only verification, no artifacts created

---

## Contract 4: `aiops dispatch --run <RUN_ID> [flags]`

**Purpose**: Execute a plan's dispatch step (codex execution or fallback) and optionally verify.

### Prerequisites
- `reports/ai_runs/<RUN_ID>/plan.md` exists
- `reports/ai_runs/<RUN_ID>/codex_task.txt` exists (generated by plan or provided manually)

### Behavior
1. If `codex` CLI is available on PATH:
   - Execute `codex exec "<task_content>"` with 1800s timeout
   - Capture output deterministically
2. If `codex` CLI not available:
   - Return EXIT_NEEDS_OPERATOR (2)
   - Write `codex_task.txt` to run directory for manual execution

### Exit Codes
- `0`: Dispatch + optional verify both succeeded
- `1`: Plan artifacts missing or dispatch failed
- `2`: NEEDS_OPERATOR (codex unavailable, manual task file provided)
- `3`: Verify failed after dispatch succeeded

### Invariants
- **No secrets in stdout**: Environment variables (OPENAI_API_KEY, etc.) not printed
- **Timeout safety**: Codex execution bounded to 1800 seconds (configurable via ENV)
- **Fallback behavior**: Preserved codex_task.txt file for operator manual execution

---

## Contract 5: `aiops run <spec> [--mode BUILD]`

**Purpose**: Execute parse → plan → dispatch end-to-end, returning overall exit code.

### Exit Codes
- `0`: All stages succeeded
- `1`: Parse or plan failed
- `2`: Dispatch returned NEEDS_OPERATOR
- `3`: Other dispatch or verify failure

### Invariants
- **Single entry point**: Combines parse, plan, dispatch for CI usage
- **Deterministic stdout**: Same spec always produces same output structure

---

## Contract 6: `aiops run-all --spec <spec> --mode <MODE>`

**Purpose**: Execute full lifecycle (parse → plan → dispatch → run → verify) with deterministic summary artifacts.

### Stdout (Always)
Minimal output:
- On success: Four 4-line artifact location lines (from plan stage)
- On failure: "RUN_ALL_STATUS: <status>" (error details to stderr)

### Artifacts Created
1. `reports/ai_runs/<RUN_ID>/run_all_summary.md`: Markdown table of stage exit codes and final status
   - No timestamps beyond RUN_ID
   - Stable section ordering
   - Row order: parse, plan, dispatch, run, verify

### Exit Codes
- `0`: EXIT_OK — All stages succeeded
- `2`: EXIT_NEEDS_OPERATOR — Dispatch returned NEEDS_OPERATOR, or early operator intervention required
- `3`: EXIT_VERIFY_FAILED — Run succeeded but verify failed
- `4`: EXIT_PARSE_OR_PLAN_FAILED — Parse or plan failed
- `5`: EXIT_DISPATCH_FAILED — Dispatch failed (not NEEDS_OPERATOR)
- `6`: EXIT_RUN_FAILED — Run stage failed

### run_all_summary.md Format
```markdown
# AIOps Run-All Summary

## Inputs
- RUN_ID: <run_id>
- SPEC_PATH: <spec_path>
- MODE: <mode>

## Stage Results
| Stage | Exit Code |
|---|---|
| parse | <code> |
| plan | <code> |
| dispatch | <code> |
| run | <code> |
| verify | <code> |

## Final
- RUN_ALL_STATUS: <status>
- EXIT_CODE: <code>

```

### Invariants
- **Deterministic**: Same spec + mode always produces same summary structure
- **No operator secrets**: Summary artifacts contain no OPENAI_API_KEY, AWS keys
- **Stable ordering**: Stage results always in order: parse, plan, dispatch, run, verify
- **Early exit**: If parse/plan fail, dispatch/run/verify marked -1; summary still written
- **Summary written before exit**: Even on failure, summary.md persisted to disk

## Integration Contracts

### No External API Calls from Python
- Codex CLI invocations allowed only via subprocess
- No direct OpenAI API, AWS API, or other external service calls from aiops Python modules
- All external execution deferred to codex CLI or explicit subprocess calls

### No Secrets in Stdout/Stderr
- OPENAI_API_KEY, AWS_*, ALPHACA_* env vars never printed
- Codex task text may contain secrets (passed to CLI), but return output filtered
- Summary artifacts contain only metadata (RUN_ID, SPEC_PATH, exit codes)

### No Randomness
- No random seed setting between runs
- No UUID generation (use deterministic RUN_ID based on timestamp + git SHA)
- Same input always produces same output

### Minimal Stdout
- `aiops plan` prints exactly 4 artifact lines
- `aiops run-all` prints 4 artifact lines + final status line (5 total)
- All other output to stderr (progress, errors, logs)

### Directory Structure After Successful Workflow
```
reports/ai_runs/<RUN_ID>/
├── plan.md                    (canonical plan with PLAN_HASH)
├── spec_snapshot.md           (copy of input spec at plan time)
├── codex_task.txt             (if generated; optional if manual)
├── run_all_summary.md         (if run-all executed)
└── [run stage outputs]        (if run stage executed)
```

## Test Coverage

All contracts enforced by:
- **test_aiops_contracts.py**: Golden tests for determinism, exit codes, artifact formats
- **test_aiops_plan.py**: Plan output stability, RUN_ID format, plan.md hash consistency
- **test_aiops_dispatch.py**: Codex detection, secret filtering, NEEDS_OPERATOR fallback
- **test_aiops_run_all.py**: Full lifecycle orchestration, summary generation, exit code branching

### Golden Test Pattern
```python
# Golden test: fixture inputs -> expected artifacts (deterministic)
def test_plan_deterministic_on_same_spec(fixture_spec_path, tmp_path):
    exit1, run_id1 = plan (fixture_spec_path)
    exit2, run_id2 = plan(fixture_spec_path)
    
    assert run_id1 == run_id2  # same run ID
    assert plan1_md == plan2_md  # same plan content
    assert run_id1.count('-') == 2  # format YYYYMMDD_HHMMSS_sha
```

## Operator Runbook

### Silent Failures
If exit code is 4 (PARSE_OR_PLAN_FAILED):
```bash
aiops parse specs/my_spec.md          # Diagnose parse failures
cat reports/ai_runs/*/spec_snapshot.md  # Check what was snapshotted
```

### Codex Unavailable (Exit 2: NEEDS_OPERATOR)
```bash
which codex  # Check installation
brew install codex  # Or npm install -g @codex-js/cli
codex --help  # Validate install

# OR manually execute task:
cat reports/ai_runs/<RUN_ID>/codex_task.txt
codex exec "<task_text>"
```

### Verify Failed (Exit 3: VERIFY_FAILED)
```bash
cat reports/ai_runs/<RUN_ID>/run_all_summary.md  # See which stage failed
aiops verify specs/my_spec.md --mode HARDEN  # Re-run verify in isolation
```
